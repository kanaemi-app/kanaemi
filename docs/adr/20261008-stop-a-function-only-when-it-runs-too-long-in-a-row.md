# 長く動き続けた関数は、続けてそうなったときだけ止める

状態：採用

## 背景

関数は、打つのを止めないよう、決まった時間を過ぎると打ち切る。これまでは、一度打ち切った関数を、関数を読み直すまで呼ばなかった。

時間を過ぎるのは、関数が終わらないときだけではない。機械が混んでほかのプログラムに CPU を譲ったときや、メモリの回収で止まったときも、ふだんは一瞬で終わる関数が時間を過ぎる。一度のそれで、組み込みの日付の関数などが、利用者の気づかないまま、設定のフォルダが変わるまで使えなくなっていた。

## 決定

- 時間を過ぎた呼び出しは、これまでどおりその場で打ち切る。一度の変換が待たせる長さは変わらない。
- 関数を呼ばなくするのは、何度か続けて時間を過ぎたときだけにする。間に時間内に終わった呼び出しがあれば、数え直す。呼ばなくした関数は、これまでどおり読み直すまで呼ばず、そのことをログに残す。
- ファイルを読むときに時間を過ぎたら、何度か続けてそうなるまで読み直す。ファイルは関数を読み直すまで一度しか読まないので、一度の止まりで関数がなくなるため。
- 時間は、これまでどおり実際に過ぎた時間で測る。

## 検討した他の案

- スレッドが使った CPU 時間で測る：ほかのプログラムに譲った間は数えないが、利用者が待つのは実際に過ぎた時間で、待たせる長さを抑えられない。メモリの回収で止まった分は CPU 時間にも入り、測り方も OS ごとに違う。
- Luau の命令の数で測る：毎回同じに数えられるが、Luau が割り込みを確かめるのはループや関数の呼び出しのときだけで、標準ライブラリの 1 回の呼び出しにかかる長さを数えない。待たせる長さを抑えられない。
- 時間を過ぎた関数を、しばらく呼ばずに置いてから、また呼ぶ：本当に終わらない関数が、その間をおくたびに打つのを止め続ける。
- 時間の上限を長くする：止まりの長さに上限はなく、終わらない関数が毎回長く待たせる。

## 結果

- 一度の止まりでは、関数は使えなくならない。
- 終わらない関数は、呼ばなくなるまでの何度か、打つのを時間の上限だけ待たせる。
- 読むと終わらないファイルは、読むたびに、何度か時間の上限だけ待たせる。
