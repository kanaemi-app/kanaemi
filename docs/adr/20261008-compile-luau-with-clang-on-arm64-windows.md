# ARM64 の Windows では、Luau を clang でコンパイルする

状態：採用

## 背景

関数を動かす Luau は C++ で書かれていて、Rust のビルドの中で、各 OS の標準の C++ コンパイラでコンパイルしている。ARM64 の Windows の MSVC は、最適化をかけると、Luau の状態を作る関数を誤ってコンパイルする。書いていないスタックの値をポインタとして読み戻すので、新しい状態の一部が初期化されないまま残り、どこかのメモリが書き潰される。リリースビルドのテストが落ち、入力方式の DLL はアプリが終わるときに落ちる。

デバッグビルドと x64 では起きない。CI はデバッグビルドで、x64 でしかテストしていなかったので、見つからなかった。

## 決定

- ARM64 の Windows では、Luau を MSVC ではなく、MSVC と互換の clang（clang-cl）でコンパイルする。Rust と C のコード、ほかの OS とアーキテクチャのコンパイラは変えない。
- CI で、ARM64 の Windows のリリースビルドで、Luau を使うテストを走らせる。

## 検討した他の案

- Luau だけ、MSVC で速さでなく大きさを優先して最適化する：確かめた限りでは直るが、誤りを避けられるのは最適化の結果がたまたま違うからで、理由は分かっていない。Luau やコンパイラの版が変われば、また踏みうる。
- Luau を含むクレートの最適化レベルを、Cargo で下げる：上と同じく避けられる理由がない。ほかの OS とアーキテクチャの Luau まで遅くなる。
- Luau の切り替え（fflag）で、状態の初期化を新しい書き方に変える：誤る関数を通らなくなるだけで、誤ってコンパイルされたコードは残る。切り替えは Luau が移行のために置くもので、版が上がると消える。
- MSVC が直るのを待つ：その間、ARM64 の Windows の利用者の手元で落ち続ける。

## 結果

- ARM64 の Windows でビルドするには clang-cl が要る。暗号のクレート（ring）がこのターゲットで clang をすでに求めていて、clang-cl は同じ LLVM に入っているので、入れる道具は増えない。
- Luau をコンパイルするコンパイラが、ARM64 の Windows だけ、同じ Windows の x64 とも違う。
- リリースビルドの Luau は、ARM64 の Windows で CI が動かして確かめる。
