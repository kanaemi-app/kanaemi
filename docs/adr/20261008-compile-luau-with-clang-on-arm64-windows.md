# ARM64 の Windows では、Luau を clang でコンパイルする

状態：採用

## 背景

関数を動かす Luau は C++ で書かれていて、各 OS の標準の C++ コンパイラでコンパイルしていた。ARM64 の Windows の MSVC は、最適化をかけると、Luau の状態を作る関数を誤ってコンパイルする。新しい状態の一部が初期化されないまま残り、どこかのメモリが書き潰される。リリースビルドのテストが落ち、IME はアプリが終わるときに落ちる。

デバッグビルドと x64 では起きない。CI はデバッグビルドで、x64 でしかテストしていなかったので、見つからなかった。

## 決定

ARM64 の Windows では、Luau を MSVC ではなく、MSVC と互換の clang（clang-cl）でコンパイルする。

- ほかのコード、ほかの OS とアーキテクチャのコンパイラは変えない。
- ARM64 の Windows のリリースビルドで Luau を動かすことを、CI で確かめる。

## 検討した他の案

- Luau だけ、MSVC で大きさを優先して最適化する：確かめた限りでは直るが、避けられるのは最適化の結果がたまたま違うからで、理由は分かっていない。Luau やコンパイラの版が変われば、また踏みうる。
- Luau を含む部分の最適化を弱める：上と同じく避けられる理由がなく、ほかの OS とアーキテクチャの Luau まで遅くなる。
- Luau の移行用の切り替えで、状態を作る別の道を通す：誤る関数を通らなくなるだけで、誤ってコンパイルされたコードは残る。切り替えは Luau の版が上がると消える。
- MSVC が直るのを待つ：その間、ARM64 の Windows の利用者の手元で落ち続ける。

## 結果

- ARM64 の Windows でビルドするには clang-cl が要る。
- Luau をコンパイルするコンパイラが、ARM64 の Windows だけ、同じ Windows の x64 とも違う。
