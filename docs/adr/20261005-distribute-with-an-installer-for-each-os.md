# OS ごとのインストーラーで配る

状態：採用

## 背景

入力方式は、ファイルを置くだけでは使えない。OS が入力方式を探す場所に置き、OS に登録し、消すときは登録を外す必要がある。いまはソースからビルドして入れるスクリプトしかなく、ビルドの環境を持たない利用者は入れられない。

## 決定

- OS ごとに、その OS でソフトウェアを入れる普通の仕組み（インストーラーやパッケージマネージャー）に合わせた形で配る。置く、登録する、消すときに外す、をその仕組みに任せる。
- 配るものは、リリースのタグからビルドする。

## 検討した他の案

- インストールのスクリプトを配る：ビルドの環境が要り、消す手順もない。
- アーカイブを配って手で置いてもらう：置き場所と、登録とその解除を、利用者が間違えやすい。
- OS をまたぐ 1 つのサンドボックスの形式（Flatpak など）で配る：入力方式は、ほかのアプリの入力を受けるために OS の側で動く必要があり、サンドボックスの中からは登録できない。

## 結果

- OS ごとに配る形を作る手順を持ち、リリースのたびにすべて作る必要がある。
- どの OS 向けにも、入れ方と消し方が、その OS のほかのソフトウェアと同じになる。
