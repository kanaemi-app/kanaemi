# Windows では、ユーザーデータの書き込みを別のプロセスに任せる

状態：採用

## 背景

Windows の IME（TIP）は各アプリのプロセスに読み込まれ、AppContainer のプロセスの中でも動く。AppContainer の中からは、ユーザーのディレクトリを読むことも書くこともできない（[Windows（TSF）](../references/windows.md)）。

## 決定

- Windows では、ユーザーカスタム辞書への書き込みを、TIP とは別の、ユーザーの権限で常駐するプロセスに任せる。TIP は書き込む内容を送るだけにする。
- AppContainer の中の TIP には、利用者が打った語を含むものを読ませない。読ませるのは、それを含まないものだけにする。
- 書き込み用のプロセスは、送られてきたものを、正しいユーザーデータとして読めるかを確かめてから書く。

## 検討した他の案

- 誰でも書ける場所に置く：AppContainer からは書けず、権限を広げると他のアプリからも書き換えられる。
- ユーザーデータをすべて AppContainer に読ませる：どの AppContainer のアプリからも、利用者が打った語を読めてしまう。
- 変換も書き込み用のプロセスで行う：キーごとにプロセスをまたぐと、そのプロセスが止まったときに入力も止まる。

## 結果

- AppContainer のアプリでも、辞書登録したものは書き込まれ、ほかのアプリで使える。
- AppContainer のアプリでは、利用者が打った語に基づくもの（ユーザーカスタム辞書の語やよく選ぶ候補）は効かない。
- 書き込み用のプロセスが止まっても、TIP はその応答を待たずに変換と入力を続ける必要がある。
