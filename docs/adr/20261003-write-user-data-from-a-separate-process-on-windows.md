# Windows ではユーザーデータの書き込みを別プロセスに任せる

状態：採用

## 背景

Windows の IME（TIP）は各アプリのプロセスに読み込まれ、AppContainer のプロセスの中でも動く。AppContainer の中からは、ユーザーのディレクトリを読むことも書くこともできない（[Windows（TSF）](../references/windows.md)）。

## 決定

- Windows では、ユーザーカスタム辞書への書き込みを、ログイン時に起動する別プロセスに任せる。TIP は書き込む内容を送るだけにする。
- TIP と書き込み用のプロセスは名前付きパイプでつなぐ。
- 書き込み用のプロセスは、AppContainer に、設定ファイル・辞書・ローマ字の表・並べ替えのモデルだけを読ませる。利用者が打った語を含むファイル（ユーザーカスタム辞書・よく選ぶ候補の記録）は読ませない。
- AppContainer の中の TIP は、利用者が打った語を読みも書きもしない。辞書登録と削除の行だけをパイプで送り、よく選ぶ候補は記録しない。
- パイプは、AppContainer にはデータを書く権限だけを与える。書き込み用のプロセスは、ユーザーカスタム辞書として読める 1 行だけを受け付ける。

## 検討した他の案

- 誰でも書ける場所に置く：AppContainer からは書けず、権限を広げると他のアプリからも書き換えられる。
- 設定のフォルダ全体を AppContainer に読ませる：どの AppContainer のアプリからも、利用者が打った語を読めてしまう。
- 変換を書き込み用のプロセスで行う：キーごとにプロセスをまたぐと、そのプロセスが止まったときに入力も止まる。

## 結果

- 書き込み用のプロセスが止まったり応答しなかったりしても、パイプを待って変換と入力を止めない。
- AppContainer のアプリでは、ユーザーカスタム辞書の語もよく選ぶ候補も効かない。そこで登録した語は、そのアプリの中ではすぐ使え、書き込まれてほかのアプリでも使える。
- 設定ファイルとモデルは丸ごと置き換えられるので、書き込み用のプロセスは設定のフォルダを見張り、変わるたびに読む権限を与え直す。
