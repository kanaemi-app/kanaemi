# 外からのモードの操作を、つなぎっぱなしのローカルの TCP で受ける

状態：採用

## 背景

エディタなど外のプログラムから、いまのモードを知り、モードを決めた値にしたい。たとえば Vim で挿入モードを抜けるたびに ABC にする。

呼ぶたびにプロセスを起動するコマンドで受けると、プロセスの起動が遅い Windows では、挿入モードを抜けるたびに待たされる。

## 決定

- 外からのモードの操作は、IME が待ち受けるローカルの TCP で受ける。外のプログラムは接続を張ったまま使う。
- 待ち受けは、利用者が有効にしたときだけ行う。
- つないできた相手は確かめない。操作は、そのときフォーカスのある入力欄に効く。

## 検討した他の案

- 呼ぶたびに起動するコマンド：プロセスの起動が遅い OS で、操作のたびに待たされる。
- Unix ドメインソケット・名前付きパイプ：OS ごとに口が変わり、Windows の名前付きパイプを扱えないエディタ（Vim）がある。
- 合言葉で相手を確かめる：防げるのは同じマシンのほかの OS ユーザーだけで、その相手にできるのもモードを読み、変え、見張ることに限られる。合言葉を読む手間が、つなぐ側すべてにかかる。
- 送り主のアプリが前面にいるときだけ効かせる：ターミナルの中のエディタでは前面にいるのはターミナルで、送り主を確かめられない。
- エディタのセッションごとに起動し、標準入出力で話す取り次ぎのプロセス：ソケットを扱えるエディタには余計な段になる。要るなら、TCP の待ち受けの上に足せる。

## 結果

- ソケットを扱えるエディタなら、エディタだけでつなげる。起動の待ちは最初の接続だけになる。
- 前面にいないプログラムが送ると、そのとき前面にあるアプリの入力欄のモードが変わる。
- 有効にしている間は、同じマシンのどのプログラムも、ほかの OS ユーザーのものでも、モードを読み、変え、見張れる。
- 相手を確かめないので、受ける操作は、つなげる誰に許しても困らないものに限る。打った文字・辞書・記録を読み書きする操作のように、知られたり変えられたりして困るものを足すなら、先に相手を確かめる仕組みを決め直し、この記録を置き換える。
- core には、モードを指定した値にする入力が要る。
