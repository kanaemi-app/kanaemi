# キーを処理するあいだは、ディスクにもロックにも長く待たない

状態：採用

## 背景

IME は、キーを処理するところで、利用者の打ったものをファイルに書く。登録した語はユーザーカスタム辞書に足し、よく選ぶ候補の記録はフォーカスが移るたびに書く。macOS ではキーの処理がメインスレッドなので、ここで止まると、どのアプリでも打つのが止まる。

- ユーザーカスタム辞書に語を足すときは、ロックを取れるまで待ち続けていた。設定アプリが辞書を書き直しているあいだ、ロックはそちらにある。
- よく選ぶ候補の記録は、ディスクまで書き出してから置き換えていた。macOS ではこの書き出しに数百 ms かかることがあった。

## 決定

- キーを処理するあいだは、ロックを短くしか待たない。取れなければ書かずに、まだ書いていないものとしてメモリに持ち、あとで書き直す。
- キーを処理するあいだは、ディスクまでの書き出しを待たない。
- キーを処理しないところ（設定アプリなど）は、これまでどおり、ロックを待ち、ディスクまで書き出す。

## 検討した他の案

- 書くのを別のスレッドに移す：ディスクまで書き出す安全さは残るが、書けたかどうかをキーを処理するところに戻す仕組みが要る。書いている途中で IME が終われば失うので、失う範囲は大きく変わらない。
- 書き出しを何回かに一度にする：その一度は同じだけ止まる。
- 速いが弱い書き出しを使う：短くはなるが、ディスクの速さしだいで止まり、macOS ではディスクに届いたことにならない。
- ロックをやめ、待たずに足す：設定アプリの書き直しと重なると、足した語が消える。

## 結果

- キーを処理するあいだは、ロックを短い時間しか待たず、ディスクへの書き出しは待たない。
- 設定アプリが辞書を書き直しているあいだに登録した語は、その場ではファイルに書かれず、あとで書かれる。その前に IME が終わると、その語は失う。
- IME だけが落ちたときは、書いたものは失わない。OS が落ちたときや電源が切れたときは、ディスクに届いていなかった分を失う。よく選ぶ候補の記録は、すべて失うこともある。記録は並べ替えの手がかりで、打つうちにまた覚えるので、受け入れる。
