# Windows では、スレッドの状態を TIP が非アクティブになるときに手放す

状態：採用

## 背景

Windows の IME（TIP）は、アプリのスレッドごとに、設定・辞書・関数（Luau）を読み込んだ状態を持つ。これまではスレッドローカル変数に入れたまま、手放す時を決めていなかった。

スレッドローカル変数は、スレッドが終わるときか DLL が外されるときに片付けられる。Windows ではどちらもローダーロックを握ったまま動く。アプリが COM を終えると、`DllCanUnloadNow` が断っても COM は DLL を外す（[Windows（TSF）](../references/windows.md)）。そのとき、ローダーロックの中で Luau のメモリの回収が全部走り、ファイルや COM のオブジェクトも閉じていた。ローダーロックの中でこうしたことをすると、ほかのスレッドと待ち合ってアプリが止まったり、先に外された DLL を呼んだりしうる。IME が原因でアプリが止まってはならない。

制御の接続のスレッドも、DLL が外されたあとに目を覚ますと、もうないコードを動かしてアプリを落とす。

## 決定

- スレッドの状態は、そのスレッドで最後の TIP が非アクティブになるとき（`ITfTextInputProcessor::Deactivate`）に手放す。TIP がまたアクティブになったら、読み込み直す。
- 手放す前に、フォーカスが外れたときと同じく、まだ書いていないよく選ぶ候補の記録を書く。辞書登録は、これまでどおり登録したときに書く。
- アクティブな TIP がないスレッドでは、状態を読み込まない。
- スレッドローカル変数が片付けられるときにまだ状態が残っていたら、手放さずに置いていく。
- TIP が自分のスレッドを起こすときは、先に DLL をプロセスが終わるまで外させない。

## 検討した他の案

- これまでどおりスレッドローカル変数の片付けに任せる：ローダーロックの中で関数のメモリの回収やファイルの片付けが走る。
- スレッドローカル変数の片付けでは、いつも置いていく：状態は TIP が非アクティブになっても残り、手放す時がない。DLL を読み込んでは外すアプリでは、外すたびに置いていく分が積み重なる。
- スレッドが終わるときに手放す：スレッドの終わりを知る手段（スレッドローカル変数の片付け、`DLL_THREAD_DETACH`）は、どれもローダーロックの中で動く。
- DLL をいつも外させない：DLL を外すときの危うさはなくなるが、スレッドが終わるときやプロセスが終わるときの片付けは、やはりローダーロックの中で動く。
- フォーカスが外れるたびに手放す：フォーカスはたびたび動き、そのたびに辞書と関数を読み込み直すと、打ち始めが遅れる。

## 結果

- IME を切り替えて戻すと、そのスレッドの状態を読み込み直す。新しいスレッドで初めて打つときと同じだけ待つ。
- 置いていくのは、TIP が非アクティブにならないまま、スレッドが終わるか DLL が外されるときだけ。ふつうは TSF が先に TIP を非アクティブにするので、積み重ならない。
- よく選ぶ候補の記録を、ほかのプロセスが書いていて書けなかったときは、その分を失う。これまでは次にフォーカスが動いたときに書いていた。
- AppContainer のアプリでは、そこで登録した語は読み込み直すと消える（書き込み用のプロセスが書いた語は、AppContainer からは読めない）。ほかのアプリでは使える。
- 制御の接続を始めたプロセスでは、DLL はプロセスが終わるまで外れない。
