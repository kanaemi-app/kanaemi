# Linux は IBus から対応する

状態：採用

## 背景

Linux の入力の仕組みには、主に IBus と Fcitx5 がある。GNOME（Ubuntu・Fedora など）の標準は IBus で、Fcitx5 は KDE などで使われる。どちらでも、左右の Shift の単独押しと、印を付けた未確定文字列が扱える（[Linux（IBus・Fcitx5）](../references/linux.md)）。

## 決定

- 最初の Linux 版は IBus のエンジンにする。
- エンジンは Rust で書いた別のプロセスにし、D-Bus で IBus と話す。IBus のライブラリには依存しない。
- 候補の一覧は IBus のパネルに出させる。エンジンは窓を持たない。Wayland では、窓の位置をアプリ（エンジン）が決められず、カーソルのそばに窓を置けるのはパネルだけだから。
- モードが変わったことは、GNOME では IBus の補助テキストでカーソルのそばに短く出す。IBus の GTK のパネル（ほかのデスクトップ）は、補助テキストを消したあとも候補の枠を残すので、そこでは出さない。

## 検討した他の案

- Fcitx5 から始める：エンジンが C++ のアドオンになり、Rust の部分との間をつなぐ層が要る。既定の設定では左 Shift の単独押しを Fcitx5 が取る。
- IBus の C のライブラリ（libibus）を使う：GObject への依存が増え、ビルドに開発用のパッケージが要る。D-Bus の型は少なく、直接書ける。
- 候補の窓とモードの表示をエンジンが自分で描く：X11 では描けるが、Wayland ではカーソルのそばに置けない。環境で見た目が分かれるより、どこでもパネルの見た目に揃える。
- GNOME 以外では、IBus の入力モードのプロパティ（パネルのアイコン）でモードを示す：OS の入力モードの仕組みを使うことになり、パネルからもモードを切り替えられるようになる。

## 結果

- GNOME の利用者は、入力ソースに Kanaemi を足せば使える。
- 候補の一覧の見た目は、IBus のパネル（GNOME では GNOME Shell）に従い、macOS や Windows とは揃わない。
- GNOME 以外のデスクトップでは、モードが変わっても表示は出ない。
- Fcitx5 に対応するときは、別の OS ごとの入力方式として加える。
