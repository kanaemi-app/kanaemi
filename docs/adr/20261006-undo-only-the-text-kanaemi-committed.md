# 確定の取り消しは、Kanaemi が出した文字列だけにする

状態：採用

## 背景

候補を選び間違えて確定すると、消して読みから打ち直すしかなかった。直前の確定を、候補を選んでいる状態に戻したい。

ほかの IME は、入力欄の文字列を読んで確定した語を探し、その場で未確定文字列に置き換えて戻す。入力欄の文字列を読み書きできるかはアプリによって違い、同じ IME でも、戻るアプリ、別の形で戻るアプリ、何も起きないアプリに分かれる。

## 決定

直前の確定は、その語の後ろに Kanaemi が出した文字列だけが続いている間に限って取り消せる。

- 入力欄の文字列は読まない。Kanaemi が覚えている、確定した語とその後ろに出した文字列を消してから、確定したときの候補の並びと選んでいた候補のまま、候補を選んでいる状態に戻す。
- キャレットが動いたかは確かめず、動かしうる操作があったら取り消せなくする。動かしうる操作は広めに拾う。
- 消すための操作をアプリに届けられなかったときは、戻さない。
- 取り消した確定からは、学ばなかったことにする。

## 検討した他の案

- 入力欄の文字列を読んで、確定した語を探す：キャレットを動かしたあとでも戻せるが、アプリによって結果が変わり、どの OS でも同じに動かせない。
- 選んだ文字列を読みに戻して変換し直す：表記から読みを引く辞書が要り、入力欄の文字列を読むことも要る。
- 戻したあとも、学んだままにする：間違えて確定した語が、学んだ並びで前に出てしまう。

## 結果

- Kanaemi は、直前に確定した語と、その後ろに出した文字列を覚える。
- OS ごとの入力方式は、キャレットの前の文字列を消す手段と、キャレットを動かしうる操作を知る手段を持つ。
- キャレットを動かしたあとには戻せない。アプリが Kanaemi に知らせずに文字を足したあと（括弧を閉じるなど）に戻すと、消す文字列がずれる。
- 消せたかどうかは確かめない。アプリが消すための操作を受け付けないと、元の文字列が残ったまま選び直すことになる。
