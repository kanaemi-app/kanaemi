# 確定の取り消しは、Kanaemi が出した文字列だけにする

状態：採用

## 背景

候補を選び間違えて確定すると、消して読みから打ち直すしかなかった。直前の確定を、候補を選んでいる状態に戻したい。

ほかの IME は、入力欄の文字列を読んで確定した語を探し、その場で未確定の文字列に置き換えて戻す。入力欄の文字列を読み書きできるかはアプリによって違い、同じ IME でも、戻るアプリ、別の形で戻るアプリ、何も起きないアプリに分かれる。

## 決定

- 直前に候補を確定した語を、確定したときの候補の並びと選んでいた候補のまま、候補を選んでいる状態に戻せるようにする。
- 戻せるのは、その語を確定してから、Kanaemi が出した文字列だけが後ろに続いている間にする。キーをアプリに渡したとき、フォーカスが移ったとき、マウスのボタンを押したときに戻せなくなる。キャレットが動いたかを確かめる代わりに、動かしうる操作を広めに拾う。
- 入力欄の文字列は読まない。Kanaemi が覚えている、確定した語とその後ろに出した文字列を、入力欄から消してから戻す。
- 消すための操作がアプリに届いてから、候補を選んでいる状態にする。届けられなかったときは戻さない。
- 取り消した確定は、学ばなかったことにする。

## 検討した他の案

- 入力欄の文字列を読んで、確定した語を探す：キャレットを動かしたあとでも戻せるが、アプリによって結果が変わり、どの OS でも同じに動かせない。
- 選んだ文字列を読みに戻して変換し直す：読みを表記から逆に引く辞書が要り、入力欄の文字列を読むことも要る。
- 戻したあとも、学んだままにする：間違えて確定した語が、確定履歴とよく選ぶ候補で前に出てしまう。

## 結果

- core は、直前に確定した語と、その後ろに出した文字列を覚える。
- OS ごとの入力方式は、キャレットの前の文字列を消し、消し終えたことを core に伝える手段と、マウスのボタンが押されたことを知る手段を持つ。
- キャレットを動かしたあとには戻せない。アプリが Kanaemi に知らせずに文字を足したあと（括弧を閉じるなど）に戻すと、消す文字列がずれる。
- 消せたかどうかは確かめない。消すための操作をアプリが受け付けないと、元の文字列が残ったまま選び直すことになる。
