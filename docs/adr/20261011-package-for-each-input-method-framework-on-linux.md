# Linux では、入力の仕組みごとに、それだけで入るパッケージを配る

状態：採用

## 背景

Linux の入力方式は、IBus か Fcitx5 のどちらかの上で動き、使う人はどちらか一方を使う。Fcitx5 のアドオンは Fcitx5 のライブラリに対してビルドされ、それがないと読み込めない。IBus のエンジンは Fcitx5 を要らない。ほかの入力方式も、IBus 用と Fcitx5 用を別のパッケージで配っている。

## 決定

Linux では、IBus 用と Fcitx5 用を別のパッケージにする。どちらも、それだけを入れれば使えるよう、設定アプリを含める。

## 検討した他の案

- 両方を 1 つのパッケージに入れる：配る形は 1 つで済む。しかし、IBus しか使わない人にも Fcitx5 のライブラリを入れさせるか、Fcitx5 を入れないまま読み込めないアドオンを置くことになる。
- 設定アプリを共通のパッケージに分け、両方がそれに頼る：ファイルの重なりはなくなる。しかし、リリースから入れる人は、2 つのパッケージを選んで入れる必要がある。

## 結果

- リリースの Linux のインストーラーは、入力の仕組みごとにある。どれがどの仕組み用かを、目録で見分けられる必要がある。
- 2 つのパッケージは、同じファイルを持たない。両方を入れてもぶつからない。
- 設定アプリは 2 つのパッケージに重ねて入る。
