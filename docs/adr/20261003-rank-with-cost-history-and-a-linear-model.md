# 辞書のコストと確定履歴と線形モデルで並べる

状態：採用

## 背景

並べ替えは手元で一瞬で終わり、同じ入力と同じ文脈なら毎回同じ結果を返す必要がある。

## 決定

- 候補は、辞書のコスト、入力欄ごとの確定履歴、直前の文脈を特徴にした線形モデルで並べる。モデルは確定履歴の候補も含めたすべての候補を並べ、確定履歴は先に出す決まりではなく特徴として効かせる。
- モデルがないときは、確定履歴にある候補を辞書をまたいで先に出し、残りを辞書の優先度とコストの順に並べる。
- 確定履歴はフォーカスが移ったら捨てる。
- 入力欄をまたいで何度も選んだ候補は、記録して先に出す。1 度選んだだけでは順を変えず、古い選択ほど軽くする。
- モデルは利用者の手元で学習し直さない。学習は辞書を作る側が行う。選んだ記録も学習には使わない。
- 直前の文脈は、その入力欄で IME が確定した文字から取る。
- 特徴の作り方は Kanaemi が 1 つだけ定め、学習する側も同じ作り方を使う。

## 検討した他の案

- 辞書のコストと確定履歴だけで並べる：線形モデルを足した方が、評価で明確に良かった。
- 文脈と候補を別々にベクトルにする二塔型：線形モデルに届かなかった。
- 直前に選んだ候補を先頭に出す学習：1 度選んだだけで、場面を問わず順位が変わる。
- 選んだ記録で手元のモデルを学習し直す：結果が利用者ごとに変わり、学習する側の評価と食い違う。
- 直前の文脈をアプリから読む：読めないアプリがあり、同じ入力でもアプリによって並びが変わる。
- モデルがないとき、辞書の優先度を確定履歴より先にする：直前に確定した語でも、優先度の低い辞書の語なら下に沈む。

## 結果

- 学習する側は Kanaemi の特徴の作り方に依存する。特徴を変えると、モデルを学習し直す必要がある。
- モデルがないとき、辞書をまたいでコストどうしは比べない。
- 選んだ記録は、読みと表記を残す。利用者が打った語を表すので、持ち主だけが読めるファイルにし、いつ選んだかは残さず、利用者が消せるようにする。
