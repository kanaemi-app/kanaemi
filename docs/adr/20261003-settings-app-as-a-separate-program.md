# 設定アプリを IME とは別のプログラムにする

状態：採用

## 背景

辞書の並べ替えや、出さないことにした語を戻す操作、キーの割り当てのように、数の多い設定には画面が要る。一方、IME はすべての入力を受けるので、止まると文字を打てなくなる。

## 決定

設定アプリは IME とは別のプログラムにする。IME とは直接やり取りせず、IME が読む設定や辞書のファイルを読み書きすることで変更を渡す。

## 検討した他の案

- IME のプロセスで設定の画面を開く：画面のための部品を IME が抱え込み、画面の不具合で入力まで止まりうる。
- 別のプログラムにし、IME と直接やり取りして変更を渡す：設定は手で書いたファイルでもできるので、ファイルのほかに渡し方がもう 1 つ増える。IME が設定アプリの応答を待つ場面もできる。

## 結果

- IME は画面のための部品を持たず、画面の不具合で入力が止まらない。
- 設定アプリで変えたことは、IME がファイルを読み直したときに効く。
- 手で書いたファイルと設定アプリが同じファイルを触るので、設定アプリは IME と同じ規則で読み、IME が読めない値は書かない。
