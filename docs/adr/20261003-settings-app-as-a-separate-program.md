# 設定アプリを別のプログラムにする

状態：採用

## 背景

辞書の並べ替えや変換、出さないことにした語を戻す操作、キーバインドのように数の多い設定には画面が要る。一方、IME はすべての入力を受けるので、止まると文字を打てなくなる。

## 決定

- 設定アプリは IME とは別のプログラムにし、Dioxus で作る。各 OS の IME のメニューから起動する。
- IME との通信は持たない。読み書きするのは、設定のフォルダのファイル（設定ファイル、辞書、ユーザーカスタム辞書、よく選ぶ候補の記録）と、IME のログだけにする。
- IME は、入力欄にフォーカスが入るとき、変わったファイルを読み直す。

## 検討した他の案

- IME のプロセスで設定の画面を開く：画面のための部品を IME が抱え込み、画面の不具合で入力まで止まりうる。

## 結果

- IME は、キーを扱う常駐のプロセスのままでいられる。
- 出さないことにした語を戻す操作は、入力の流れではなく設定アプリで行う。
- 設定アプリで変えたことは、次に入力欄にフォーカスが入ったときに効く。
- 設定ファイルは手でも書けるので、設定アプリは IME と同じ規則で読み、IME が読めない値は書かない。
