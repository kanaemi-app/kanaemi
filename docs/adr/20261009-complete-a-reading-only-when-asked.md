# 読みの補完は、利用者が頼んだときだけ行う

状態：採用

## 背景

長い読み（長い語や、よく打つ固有名詞）は、最後まで打つのが手間になる。SKK は、読みの途中でキーを押すと、打った読みで始まる見出しに置き換える補完を持ち、SKK の打ち方に慣れた利用者はこれを使う。

一方、Kanaemi は利用者が指示したときだけ変換し、打つたびに出る予測候補は持たない（[コンセプト](../concept.md)）。補完を入れるなら、この原則に合う形にする必要がある。

## 決定

- 読みの補完は、利用者が補完のキーを押したときだけ行う。打っている間に勝手には出さない。
- 補完は、いま打った読みを、それで始まるより長い読みに置き換えるだけにする。続けて押すと次の読みに置き換え、一巡すると打った読みに戻る。
- 補完した読みは、打った読みと同じに扱う。変換は、ふだんどおり利用者が頼んだときに行う。
- 補完する読みは、この入力欄で確定した読み、よく選ぶ候補の読み、辞書の読みから出す。利用者が打ったことのある読みを先に出す。

## 検討した他の案

- 打つたびに、補完できる読みや候補を出す（予測入力）：打ったそばから画面が変わり、利用者が指示したときだけ変換する原則に反する。
- 補完で、読みの代わりに、その読みを変換した語を出す：利用者が頼む前に変換することになる。
- SKK のように、最後の読みで止まる：打った読みに戻るには、消して打ち直す必要がある。戻れる方が、試しに押しても失うものがない。
- 辞書の読みだけから出す：利用者がよく打つ読みが、辞書の多くの読みの後ろに回る。

## 結果

- 補完のキーは、読みを打っているあいだはアプリに渡らなくなる。
- 変換器は、変換に加えて補完の読みを出す。大きな辞書から短い読みで補完すると、引く読みが多くなるので、引く数に上限を置く。そのぶん、目当ての読みを見落とすことがある。
