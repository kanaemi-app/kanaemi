# 読みの補完は、利用者が頼んだときだけ行う

状態：採用

## 背景

長い読み（`;kakuninnshitekudasai` のような語や、よく打つ固有名詞）は、最後まで打つのが手間になる。SKK は、読みの途中で Tab を押すと、打った読みで始まる見出しに置き換える補完を持ち、SKK の打ち方に慣れた利用者はこれを使う。

一方、Kanaemi は「利用者が指示したときだけ変換する」を原則にしていて、打つたびに出る予測候補は持たない。補完を入れるなら、この原則に合う形にする必要がある。補完する読みをどこから出し、どう並べるかも決める必要がある。

## 決定

- 読みの場面に、読みを補完する機能を置く。キーに割り当てて押したときだけ働き、打っている間に勝手には出さない。既定は Tab で、逆向きに回る機能を Shift+Tab に置く。ほかの機能と同じく、キーは設定で変えられる。
- 補完は、いま打った読みで始まる、それより長い読みに、読みを置き換える。続けて押すと次の読みに置き換え、最後の次は打った読みに戻る。逆向きは前の読みに置き換え、打った読みの前は最後の読み。補完する読みがなければ何もしない。
- 補完した読みは、打った読みと同じに扱う。変換も確定も編集も、ふだんの読みの場面のまま。補完しているあいだは、補完の読みの一覧を候補と同じく出し、置き換えた読みを選んでいるものとして示す。あとどんな読みがあるかが見え、番号のキーや一覧から目当ての読みへ一度で移れる。
- 一覧が出ているあいだは、補完の一覧の場面とし、読みの場面より先に見る割り当てを持つ。そこに割り当てのないキーは、読みの場面のとおりに働くので、Space で変換、Enter で確定なども、ふだんの読みの場面と同じ。候補の一覧を動くのと同じ次・前のキーで補完を移れるようにしつつ、Space は変換のままにするため、場面を分けて割り当てる。補完のキー以外を押したら、補完は終わる。ただし、補完した読みを変換したときは、候補の場面で補完のキーを押すと、読みの場面に戻ってその次の読みに置き換える。補完していない読みを変換していたなら、その読みから補完する。変換して目当ての語でなかったときに、消して打ち直さずに次の読みへ進めるようにする。
- 送り仮名の始まりを付けたあとは補完しない。補完する読みは、送り仮名のない読みだけ。
- 補完する読みは、変換と同じく、コアの外の変換器が出す。コアは読みの一覧を受け取って順に置き換えるだけにする。
- 読みは次の順に並べ、同じ読みは 1 つにする。
  1. この入力欄の確定履歴の読み。新しく確定したものから。
  2. よく選ぶ候補の記録で、先頭へ出す重みに達した組の読み。重いものから。
  3. 辞書の一覧の読み。辞書の優先度の順に並べ、同じ辞書の中は、その読みの語のうち最も小さいコストの順、同じなら短い読み、文字の順。
- 辞書から出すのは、活用しない語を持つ読みだけ。活用する語の語幹の読み・送り仮名付きの語の読み・数の置き場所のある読みは出さない。ユーザーカスタム辞書で出さないとされた語しかない読みも出さない。
- 一度に出す読みは 100 まで。辞書ごとには、前方一致する読みを辞書の並び（文字の順）で 5000 まで見て、その中で並べる。

## 検討した他の案

- 打つたびに、補完できる読みや候補を出す（予測入力）：打ったそばから画面が変わり、「利用者が指示したときだけ変換する」原則に反する。
- 補完の一覧の場面を、読みの場面と別に一から割り当てる：読みの場面と同じに働いてほしいキーまで、すべて書き直すことになる。割り当てのないキーは読みの場面に任せれば、補完で変えたいキーだけを書けば足りる。
- 一覧が出ているあいだは、読みの場面の `next`・`previous` をそのまま補完の移動に読み替える：Space も `next` なので、補完した読みを変換できなくなる。
- 一覧が出ているあいだも読みの場面のままにする：候補の一覧と同じキー（Ctrl+N や ↓）で一覧を移れず、変換してしまう。
- 補完の読みの一覧を出さない：置き換えた読みしか見えず、目当ての読みがあるのか、あといくつ押せば届くのかが分からない。
- 一覧に、読みの代わりに、その読みを変換した語を出す：補完は読みを置き換えるもので、変換は利用者が頼んだときに行う。語を出すには、読みごとに変換することにもなる。
- SKK のように、最後の読みで止まる：打った読みに戻るには、消して打ち直す必要がある。戻れる方が、試しに押しても失うものがない。
- よく選ぶ候補の記録を確定履歴より先にする：変換の並びでは、この入力欄で確定したものが、よく選ぶ候補の記録より先に効く。補完も合わせる。
- よく選ぶ候補の記録の、1 度選んだだけの組も使う：変換では 1 度選んだだけでは並びを変えない。補完も合わせる。記録は入力欄をまたぐので、1 度打っただけの読みが、ほかの入力欄で出てくることにもなる。
- 辞書の中を、SKK と同じく読みの文字の順に並べる：あ行の後ろの読みから順に出て、よく使う語が後ろに回る。コストは辞書を作る側が頻度から付けるので、その順の方が目当ての読みに早く届く。コストを持たないテキストの辞書では、短い読みから出す。
- 並べ替えのモデルで読みを並べる：モデルは 1 つの読みの候補を並べるもので、読みどうしを比べる特徴を持たない。
- 活用する語の語幹の読みも出す：語幹（`かんがえなお`）だけでは変換しても語にならない。送り仮名付きの語は、送り仮名の始まりを付けて打つ方が早い。
- 辞書の前方一致する読みをすべて見て並べる：1 文字の読み（`か`）から補完すると、大きな辞書では数万の読みを引くことになり、キーを処理するあいだ止まる。
- 候補の場面では補完のキーをアプリに渡す：未確定文字列を残したままフォーカスが移るだけで、役に立たない。補完した読みが目当てでなかったときに、消して打ち直すことになる。
- 候補の場面の補完のキーで、いつも打った読みの最初の補完に戻る：補完した読みを変換して違ったときに、同じ読みからもう一度回ることになる。
- 候補の場面の補完のキーで、変換した読みに戻るだけにする：次の読みへ進むのに、もう一度押す必要がある。
- 既定のキーを Tab 以外（Ctrl+I など）にする：Tab は SKK の補完のキーで、慣れた利用者が多い。読みの場面で Tab をアプリに渡しても、読みを残したままフォーカスが移るだけで、役に立っていなかった。

## 結果

- コアのキーに Tab が加わり、各 OS のアプリは Tab を Tab として渡す。読みと候補の場面では、Tab はアプリに渡らなくなる。登録の場面と、何も打っていないときは、これまでどおりアプリに渡す。
- 変換器は、変換に加えて補完の読みを出す。テキストの辞書は、前方一致を探すのにすべての読みを見るので、大きな辞書ほど時間がかかる。大きな辞書はバイナリにして使う前提で、それを受け入れる。
- 短い読みから補完すると、辞書の前から 5000 の読みしか見ないので、コストの小さい読みを見落とすことがある。
- 確定履歴とよく選ぶ候補の記録から出す読みは、辞書にあるかを確かめない。確定した読みは、変換すれば同じ表記が出ることが多いため。
- キーの割り当てに、補完の一覧の場面が加わる。
