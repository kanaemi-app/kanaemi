# 公式の辞書を設定アプリから入れる

状態：採用（`20261003-dictionaries-as-an-ordered-list.md` のうち、辞書の入手を置き換える）

## 背景

公式の辞書（基本辞書と追加辞書）と、基本辞書と組の並べ替えのモデルは、Kanaemi の本体とは別に配られる。利用者が配布物を落として設定のフォルダに置き、辞書の一覧を書く必要があった。手で置くと、基本辞書とモデルの組が崩れやすく、追加辞書を基本辞書より先に並べてしまいやすい。新しい版が出たことにも気付けない。

## 決定

- 設定アプリが、公式の辞書を落として入れ、新しくする。IME は今までどおり通信しない。
- 通信するのは、利用者が設定アプリで確かめる・入れる操作をしたときだけにする。
- どの辞書があり、入れたものが最新かは、辞書を配る側が配布物と一緒に出す目録で知る。目録には配布物の中身のハッシュを載せ、落としたものはそれと合うときだけ入れる。
- 基本辞書は、組のモデルと一緒に入れて新しくする。本体が読めない版のモデルなら、基本辞書も入れない。
- 入れた辞書は、ほかの辞書と同じく設定のフォルダのファイルで、辞書の一覧で並べ替え、外せる。基本辞書は、公式の追加辞書より先に並べる。
- 辞書は今までどおり本体とは別に配り、本体にもインストーラーにも入れない。

## 検討した他の案

- 基本辞書とモデルを、ビルドのときに本体に埋め込む：辞書を直すたびに本体のリリースが要る。モデルの形式の版が本体と辞書の両方に縛られ、本体を先に新しくするとモデルを読めなくなる。辞書と本体で、ライセンスも違う。
- IME が自分で辞書を新しくする：すべての入力を受けるプロセスが通信することになり、利用者の気付かないうちに候補の並びが変わる。
- 設定アプリを開くたびに新しい版を確かめる：利用者が求めていない通信をする。
- 配る側のリポジトリのリリースを、ホスティングの API で一覧する：辞書の説明も中身のハッシュも得られず、API の回数の制限と形に縛られる。

## 結果

- 設定アプリが、HTTPS で通信し、配布物を展開する部品を持つ。
- 配る側は、目録の形を保ち、変えるときは版を上げる。
- 公式でない辞書は、今までどおり利用者が置く。
