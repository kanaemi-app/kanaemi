# 公式の辞書を設定アプリから入れる

状態：採用（`20261003-dictionaries-as-an-ordered-list.md` のうち、辞書の入手を置き換える）

## 背景

公式の辞書（基本辞書と追加辞書）と、基本辞書と組になる並べ替えのモデルは、Kanaemi の本体とは別に配られる。利用者が配布物を落として置き、辞書の一覧を書く必要があった。手で置くと、基本辞書とモデルの組が崩れやすく、追加辞書を基本辞書より先に並べてしまいやすい。新しい版が出たことにも気付けない。

## 決定

設定アプリが、公式の辞書を落として入れ、新しくする。

- 通信するのは、利用者が設定アプリで確かめる・入れる操作をしたときだけにする。IME は今までどおり通信しない。
- どの辞書があり、どれが最新かは、配る側が配布物と一緒に出す目録で知る。落としたものは、目録が示す中身と合うときだけ入れる。
- 基本辞書とモデルは、組を崩さずに入れる。本体が読めないモデルなら、基本辞書も入れない。
- 入れた辞書は、ほかの辞書と同じく辞書の一覧に並び、並べ替えも外すこともできる。
- 辞書は今までどおり本体とは別に配る。

## 検討した他の案

- 基本辞書とモデルを本体に埋め込む：辞書を直すたびに本体のリリースが要る。モデルの版が本体と辞書の両方に縛られ、本体を先に新しくするとモデルを読めなくなる。辞書と本体で、ライセンスも違う。
- IME が自分で辞書を新しくする：すべての入力を受けるプロセスが通信することになり、利用者の気付かないうちに候補の並びが変わる。
- 設定アプリを開くたびに新しい版を確かめる：利用者が求めていない通信をする。
- 配る側のリポジトリのリリースを、ホスティングの API で一覧する：辞書の説明も中身を確かめる手がかりも得られず、API の制限と形に縛られる。

## 結果

- 設定アプリが通信する。
- 配る側は目録の形を保ち、変えるときは版を上げる。
- 公式でない辞書は、今までどおり利用者が置く。
