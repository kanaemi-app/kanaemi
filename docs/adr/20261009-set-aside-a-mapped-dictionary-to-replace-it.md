# 使われているバイナリの辞書は、名前を変えてから置き換える

状態：採用

## 背景

IME はバイナリの辞書をメモリにマップして引く。新しい辞書は別の名前で書き終えてから、元の名前に名前を変えて置き換える（公式の辞書を新しくするとき、テキストの辞書を変換し直すとき）。macOS と Linux では、置き換えたあとも、読んでいるプロセスは古いファイルを引き続ける。

Windows では、どこかのプロセスがメモリにマップしているファイルは消せず、その上に名前を変えて置き換えることもできない（`MoveFileEx` は断る）。Windows の IME は文字を打つアプリのプロセスごとに読み込まれ、どれも辞書をマップするので、アプリを 1 つでも開いていれば、公式の辞書を新しくするのも、変換し直すのも、たいてい失敗する。Rust の標準ライブラリは、断られると POSIX の意味での置き換えを試すが、それが使えるのは NTFS などに限られ、マップされたファイルに効くかも確かではない。

一方、マップされているファイルでも、名前を変えることはできる（開いた側が `FILE_SHARE_DELETE` で開いていれば。Rust の標準ライブラリはそう開く）。

## 決定

- ファイルを置き換えるのを断られ、元の名前にファイルがあるときは、それを `<元の名前>.<プロセス ID>-<番号>.replaced` に名前を変えてから、新しいファイルをその名前に移す。移せなければ、名前を変えたファイルを元に戻す。
- 名前を変えたファイルは、すぐに消す。消せなければ残す。
- IME は、バイナリの辞書を開くたびに、そのファイルから名前を変えて残ったものを消そうとする。読んでいるプロセスがまだあれば消せないので、どれも読まなくなったあとに開いたときに消える。
- これは OS を問わず同じ手順にする。置き換えを断らない OS では、名前を変える手順に進まない。

## 検討した他の案

- Windows ではマップせず、メモリに読む：アプリのプロセスごとに辞書全体を持つことになる。基本辞書は大きく、アプリの数だけメモリを使う。マップならプロセスの間でページを共有できる。
- 版ごとに別の名前のファイルに書き、新しい方を読む：辞書の一覧はファイルの名前で辞書を指すので、一覧の書き方か読み方を変えることになる。置き換えのたびに一覧も書き直すか、名前から版を選ぶ決まりが要る。
- 置き換えを断られたら、次に起動したときに置き換える：IME はアプリのプロセスごとに動いていて、「どれも読んでいない時」を待つ手段がない。設定アプリが置き換えるにしても、利用者がすべてのアプリを閉じるまで新しい辞書が使えない。
- 読み込み直しを IME に頼んで、古いファイルを手放させてから置き換える：プロセスをまたいで手放したことを待つ仕組みが要り、止まっているプロセスがあると待ち続ける。

## 結果

- Windows でも、アプリを開いたまま公式の辞書を新しくし、変換し直せる。読んでいるプロセスは古いファイルを引き続け、ファイルが変わったと気付いたときに新しい方を開く。
- 古いファイルは、読むプロセスがなくなり、そのあと IME が辞書を開くまで、`.replaced` の名前で残る。そのあいだ、ディスクを 1 つ分余計に使う。
- 置き換えを断られた理由がマップ以外でも、同じ手順を試す。名前を変えるのも断られれば、初めの失敗を返す。
