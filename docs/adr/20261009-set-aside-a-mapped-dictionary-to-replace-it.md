# 使われているバイナリの辞書は、名前を変えてから置き換える

状態：採用

## 背景

IME はバイナリの辞書をメモリにマップして引く。新しい辞書は別の名前で書き終えてから、元の名前に移して置き換える。macOS と Linux では、置き換えたあとも、読んでいるプロセスは古いファイルを引き続ける。

Windows では、どこかのプロセスがメモリにマップしているファイルは消せず、その上に置き換えることもできない。Windows の IME は文字を打つアプリのプロセスごとに読み込まれ、どれも辞書をマップするので、アプリを 1 つでも開いていれば、辞書を新しくするのはたいてい失敗する。

一方、マップされているファイルでも、名前を変えることはできる。

## 決定

- 辞書の置き換えを断られたら、元のファイルの名前を変えて脇に置き、新しいファイルを元の名前に移す。
- 脇に置いたファイルは、消せるときに消す。読んでいるプロセスが残っていて消せなければ、あとで消す。
- OS を問わず同じ手順にする。置き換えを断らない OS では、脇に置くまで進まない。

## 検討した他の案

- Windows ではマップせず、メモリに読む：アプリのプロセスごとに辞書全体を持つことになる。マップならプロセスの間でページを共有できる。
- 版ごとに別の名前のファイルに書き、新しい方を読む：辞書の一覧はファイルの名前で辞書を指すので、置き換えのたびに一覧も書き直すか、名前から版を選ぶ決まりが要る。
- 置き換えを断られたら、どれも読んでいないときに置き換える：IME はアプリのプロセスごとに動いていて、どれも読んでいないときを待つ手段がない。利用者がすべてのアプリを閉じるまで新しい辞書が使えない。
- IME に古いファイルを手放させてから置き換える：プロセスをまたいで手放したことを待つ仕組みが要り、止まっているプロセスがあると待ち続ける。

## 結果

- Windows でも、アプリを開いたまま辞書を新しくできる。読んでいるプロセスは古いファイルを引き続け、ファイルが変わったと気付いたときに新しい方を開く。
- 古いファイルは、読むプロセスがなくなるまで残り、そのあいだディスクを余計に使う。
