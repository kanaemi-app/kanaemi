# 押さえたキーで、次に打つ文字の前に機能を働かせる

状態：採用

## 背景

読みと送り仮名の始まりは、場面ごとにキーへ割り当てる「始める」機能で示す（`20261003-move-between-scenes-as-you-type.md`）。SKK を使う人の多くは、読みや送り仮名を示す Shift を親指で押すために SandS（Space を押さえている間は Shift、単独で押すと Space）を使う。この指の動きのまま「始める」を使えるようにしたい。

## 決定

- 文字を打つキー（Space を含む）は、押さえたままにも機能を割り当てられる。押さえたまま文字を打つと、その機能を働かせてから文字を打つ。単独で押せば、これまでの割り当てのまま働く。単独で押したと分かるのは離したときで、そのとき押したことをアプリに渡せないので、渡す代わりにそのキーの文字を打つ。
- 押さえたままと単独で押したのとは、離す順と、押さえていた長さで見分ける。長さは修飾キーの単独押しと同じ設定を使う。

## 検討した他の案

- Space の単独押しを「始める」にする：読みの中では変換と取り合いになり、何も打っていないときは空白に 2 回押すことになる。
- 押さえたキーと文字のキーが重なれば、いつも押さえたままとする：速く打ったときの重なりで、意図しない読みが始まる。
- 押してから文字のキーを押すまでの時間だけで見分ける：速く打ったときと押さえたつもりのときとで、この時間はほとんど変わらない。
- 文字を打たないキー（Enter・変換など）も押さえたままにできるようにする：押したことをアプリに渡す代わりに打てる文字がなく、OS からキーを送り直すしかない。送れないキーや送る許可がないときに失われ、待たせた文字との順序も保てない。
- Space だけにする：文字を打つキーなら同じ仕組みで扱え、限る理由がない。

## 結果

- SandS の指の動きで、読みと送り仮名を始められる。
- 押さえたままの割り当てのあるキーは、単独で押したときの働きが離すまで遅れる。
- ホストは、修飾キーでないキーを離したことも core に伝える必要がある。
