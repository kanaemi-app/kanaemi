# 文字を打つキーを押さえたまま次の文字を打つと、そのキーの機能を先に働かせる

状態：採用

## 背景

読みと送り仮名の始まりは、場面ごとにキーへ割り当てる「始める」機能で示す（`20261003-move-between-scenes-as-you-type.md`）。SKK を使う人の多くは、読みや送り仮名を示す Shift を親指で押すために SandS（Space を押さえている間は Shift、単独で押すと Space）を使う。この指の動きのまま「始める」を使えるようにしたい。

## 決定

文字を打つキーには、押さえたままにしたときの機能を割り当てられる。押さえたまま文字を打つと、その機能を働かせてから文字を打つ。単独で押せば、そのキーのふだんの働きをする。

## 検討した他の案

- Space の単独押しを「始める」にする：読みの中では変換と取り合いになり、何も打っていないときは空白に 2 回押すことになる。
- 文字を打たないキーも押さえたままにできるようにする：単独で押したと分かるのは離したときで、そのときにはキーをアプリへ渡せない。文字を打つキーならその文字を打てば済むが、打たないキーは OS からキーを送り直すしかなく、送れないときに失われ、ほかの文字との順序も保てない。
- Space だけにする：文字を打つキーなら同じ仕組みで扱え、限る理由がない。

## 結果

- SandS の指の動きで、読みと送り仮名を始められる。
- 押さえたままの機能を割り当てたキーは、単独で押したと分かる離したときまで働きが遅れ、そのときにはキーをアプリへ渡す代わりにその文字を打つ。
- ホストは、修飾キーでないキーを離したことも core に伝える必要がある。
